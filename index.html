§ 01

Understanding the Stack

Before model selection, it is essential to understand what OpenClaw is in order to specify system requirements correctly. OpenClaw is not itself a language model — it is an infrastructure layer, an agent wrapper that connects to any LLM the user chooses (Claude, GPT, DeepSeek, Gemini, or local models via Ollama). It runs locally as a persistent background process with no browser dependency and no data sent to external servers.

In the context of a Colab deployment, the architecture has two distinct layers:

Layer 1 — Inference Backend

An Ollama server running a quantized open-weight LLM on Colab's GPU, exposed via a secure HTTPS tunnel (ngrok or localtunnel).

Layer 2 — Agent Frontend

An OpenClaw agent instance pointed at the Ollama endpoint URL, handling tool orchestration, memory, and skill execution.

Security Notice: OpenClaw does not sanitize web content before passing it to the LLM context window, making prompt injection a live architectural vulnerability. The project's own maintainers warn that if a user cannot understand how to run commands in a terminal, the project is too dangerous to use safely. All hardening steps in the Security section are non-negotiable.
§ 02

Selecting the Optimal LLM

Given the dual weighting criteria — scientific accuracy and security — the relevant benchmarks are GPQA Diamond (198 PhD-level questions in physics, biology, and chemistry), AIME 2025 (olympiad-level mathematical reasoning), and MMLU-Pro (graduate-level multitask understanding). Open-source models lag behind proprietary models by only 2–4% on GPQA Diamond as of early 2026.

// Tier Classification

S-Tier — Frontier Class (Not Colab-Feasible)

Kimi K2.5 is a mixture-of-experts model with 1 trillion total parameters (32B active per token), achieving a GPQA Diamond score of 87.6%, MATH-500 at 98.0%, and a 262K context window. Full-scale deployment requires infrastructure far beyond Colab's capacity.

A-Tier — Best Colab-Feasible Option

For scientific research in 2026, the top deployable recommendations are DeepSeek-R1 distilled variants, Qwen3 series, and THUDM/GLM-4.1V-9B-Thinking — selected for their exceptional capabilities in scientific reasoning, mathematical computation, and research applications.

// Final Recommendation by Tier

Free Tier · T4 GPU

Qwen3-8B

Q4_K_M quantized (~5 GB VRAM). Best scientific accuracy within the 15 GB T4 VRAM budget. Strong thinking-mode performance for an 8B model. Scores approximately 73% on GPQA Diamond.

Paid Tier · A100 / G4

DeepSeek-R1-Distill-32B

Q4_K_M quantized (~20 GB VRAM). Minimum viable model for production OpenClaw agentic chains. Scores approximately 83% on GPQA Diamond. Supports 65K context.

The free tier is suitable for scientific query answering and prototyping but will encounter reliability problems with complex OpenClaw agentic chains due to inherent limitations of 7–8B parameter models on tool calling.

§ 04

Free Tier Deployment

T4 GPU · 15 GB VRAM · Qwen3-8B (Q4_K_M) · ~5 GB VRAM usage

The established pattern uses Ollama as the inference backend and ngrok to create a public HTTPS tunnel. By running Ollama on Colab's GPU and exposing it via ngrok, you obtain a fully private, locally-served LLM accessible from any browser, without data sent to external APIs.

// Cell 1 — Install Dependencies & Launch Ollama

Python · Google Colab 
import subprocess, os, time, requests

# Install system dependencies and Ollama
os.system("sudo apt-get install -y pciutils")
os.system("curl -fsSL https://ollama.ai/install.sh | sh")

# Set environment variables for performance
os.environ["OLLAMA_KEEP_ALIVE"]    = "24h"
os.environ["OLLAMA_NUM_PARALLEL"]  = "1"

# Launch Ollama server in background
subprocess.Popen(
    ["ollama", "serve"],
    stdout=open("ollama.log", "w"),
    stderr=open("ollama_err.log", "w"),
    preexec_fn=os.setsid
)

# Poll until server is ready
for _ in range(30):
    try:
        if requests.get("http://localhost:11434/api/tags", timeout=2).status_code == 200:
            print("Ollama server is running.")
            break
    except:
        pass
    time.sleep(1)

// Cell 2 — Pull Recommended Model

Python · Google Colab 
# Qwen3-8B with thinking mode: best scientific accuracy within T4 VRAM budget
os.system("ollama pull qwen3:8b")
print("Model ready.")

// Cell 3 — Expose Endpoint via ngrok

Requires a free ngrok account. Register at ngrok.com and copy your authtoken from the dashboard.
Python · Google Colab 
# !pip install pyngrok  ← run this first in a separate cell
from pyngrok import ngrok

NGROK_TOKEN = "your_ngrok_authtoken_here"  # paste your token
ngrok.set_auth_token(NGROK_TOKEN)
ngrok.kill()  # kill any previous tunnels

tunnel  = ngrok.connect(11434, "http")
endpoint = tunnel.public_url

print(f"Ollama endpoint: {endpoint}")
print(f"OpenClaw config → API: openai-completions | Model: qwen3:8b | Base URL: {endpoint}")

// Cell 4 — Keep-Alive Loop

Prevents Colab from disconnecting due to inactivity. Run this in the final cell and leave it running.
Python · Google Colab 
import time

while True:
    requests.post(
        "http://localhost:11434/api/generate",
        json={"model": "qwen3:8b", "prompt": "ping", "stream": False}
    )
    time.sleep(300)  # ping every 5 minutes
§ 05

Paid Tier Deployment

Pro+ A100-80GB or RTX PRO 6000 (G4) · DeepSeek-R1-Distill-32B (Q4_K_M) · ~20 GB VRAM · 65K context

With the A100-80 GB or RTX PRO 6000, you can comfortably deploy DeepSeek-R1-Distill-32B at Q4_K_M with a full 65K context window — the minimum OpenClaw recommends for production agentic use. OpenClaw's system prompt alone consumes approximately 17,000 tokens; with sub-agent context, tool definitions, and conversation history, a 32K context minimum is required, with 65K or more recommended for production with sub-agents.

§ 06

Connecting OpenClaw

Once the Ollama endpoint is live and the ngrok tunnel URL is available, open OpenClaw's Web UI and navigate to Settings → Config. Apply the following values for each respective tier.

Field Free Tier (T4) Paid Tier (A100/G4)
API Type openai-completions openai-completions
Base URL https://xxxx.ngrok-free.app https://xxxx.ngrok-free.app
Model ID qwen3:8b deepseek-r1:32b
Context Window 8192 65536
Thinking Mode medium high

After saving Config, navigate to Agents and set the Primary Model to ollama/qwen3:8b or ollama/deepseek-r1:32b as appropriate.

Context Note: OpenClaw's system prompt alone consumes ~17,000 tokens. With sub-agent context, tool definitions, and conversation history, a 32K context minimum is required for stable agentic operation. The free-tier 8K context will truncate long agentic chains — this is the primary functional limitation of the free deployment.
§ 07

Security Hardening

Given OpenClaw's documented prompt injection vulnerabilities and the scientific/security weighting of this deployment, the following mitigations apply to both tiers without exception. Reports have documented third-party OpenClaw skills performing data exfiltration and prompt injection without user awareness, and the skill repository lacks adequate vetting to prevent malicious submissions.

01
Private ngrok tunnel only. Upgrade to a paid ngrok plan and enable IP allowlisting. Do not share the endpoint URL publicly. The free ngrok URL is publicly routable — any person with the URL can query your model.
02
Disable outbound communication skills. In OpenClaw's openclaw.json, explicitly disable email, calendar, and messaging skills unless specifically required. These are the primary exfiltration vectors.
03
Read-only file system scope. Restrict OpenClaw's workspace to a sandboxed directory. Do not point it at your home directory or any directory containing credentials, SSH keys, or API tokens.
04
No API keys in the Colab environment. Store secrets in Google Colab's built-in Secrets panel via userdata.get('KEY_NAME'), not in plaintext cells. Cells are saved to your Google Drive and are not encrypted at rest.
05
Session isolation. Each Colab session generates a fresh runtime environment. Do not persist OpenClaw's ~/.openclaw memory directory to Google Drive unless it is independently encrypted. Memory files can contain verbatim tool outputs and web-fetched content that may include injected instructions.
